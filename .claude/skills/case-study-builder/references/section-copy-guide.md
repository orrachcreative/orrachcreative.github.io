# Section-by-section copy pattern

For each section of a case study, produce three things:

**What this section proves** — the single point being made to the hiring reader. Keep this in mind so the copy doesn't wander into general description.

**Image needed** — described in plain terms (what to screenshot, not a design spec). If it's a diagram (e.g. user types and how they connect), say so plainly rather than assuming a screenshot exists.

**Placeholder copy** — draft text the user can react to and swap in real specifics for. Rules for this copy:
- Short sentences. Written to be read fast on a phone.
- No marketing language, no AI-isms ("proven ability," "leverage," "seamless," "thrive in ambiguous environments").
- No em dashes.
- State tradeoffs plainly ("this kept X simple but cost us Y") rather than implying every decision was purely upside.

## Standard section order and what each proves

1. **Hero** — this is real, shipped work, not a concept piece.
2. **The ask** — establishes how little the user started with (kills the "just executes a spec" doubt early).
3. **The real problem** — the hard part was understanding the problem, not drawing the UI. Show the users/constraints before any screens appear.
4. **Working it out** (repeat 2-3x) — this is the core of the case study. One rejected direction, one shipped direction, and the reasoning between them. If there's no real rejected direction, don't manufacture one — pick a different decision point instead.
5. **The system** (if applicable) — shows the user thinks beyond a single screen.
6. **The ecosystem** (if applicable) — shows the user can architect across multiple products/audiences on one system. Reskins/reused components go here, honestly labeled, not in "working it out."
7. **Outcome** — real signal it worked, even if soft (still in production, reused elsewhere, adopted by another team). Never invent numbers that weren't given.

Keep total per-section prose short. If a project has genuinely more to say (e.g. four decision points instead of three), prefer adding a repeat of the "working it out" block over lengthening the narrative sections.
